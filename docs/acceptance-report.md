## External evaluation decision

The initial candidate, [AgentSWE-Lite](https://github.com/VectorSpaceLab/AgentSWE), was rejected for hidden-holdout use. Its eight published tasks are public, builders have network access, and its Editing tasks call DeepSeek directly rather than Harnessa's budget ledger.

The independent evaluator selected for **public development feedback** is SWE-bench Pro V2's public split, using its published locked protocol and clean-image re-grading. It is not a hidden holdout. The official V2 description identifies a separate 858-task held-out set that is retained for internal evaluation and not published, but gives no self-service evaluator endpoint or access path. Access requires the benchmark owner, Scale, to authorize an evaluation partnership; no such account, endpoint, or agreement is present here. Use the public split for development only and do not report it as blinded generalization evidence. [Official SWE-bench Pro V2 protocol and split description](https://labs.scale.com/leaderboard/swe_bench_pro_public_v2).

The previously proposed SWE-bench Multimodal `test` submission path is **not selected**. As checked 2026-10-24, the official [`sb-cli` README](https://github.com/swe-bench/sb-cli) says `test` is available only for Lite and Verified, but later gives a `swe-bench-m test` example and repeats that command for leaderboard submissions. The official dataset guide separately lists a 500-instance Multimodal test split. These sources do not establish that a user can submit that split through the hosted service, and an authenticated quota check cannot be performed without a verified account. No key or dataset has been provisioned and no benchmark task has run.

M13's implemented local evaluator is the Harnessa-owned Harness² suite: it creates immutable grouped manifests, freezes task/spec/base/policy and route revisions, estimates bounded cost, runs matched baseline/candidate/composed experiments, and summarizes rollouts. It is not an independent evaluator. A private Harnessa-authored synthetic suite would not be independent and is not represented as a hidden benchmark. The release blocker is **Scale evaluation access for the Pro V2 held-out set**, owned by the project administrator and benchmark provider; until access is granted, holdout results remain unavailable.

## Benchmark licensing and availability

- **WorkBuddy-Bench:** Tencent's repository license says the benchmark is not intended for use within the European Union. Harnessa does not download or execute it pending documented jurisdiction/license review. This is a blocked adapter, not a zero score. [License](https://github.com/Tencent/workbuddy-bench/blob/main/LICENSE)
- **JobBench:** the official runner supports CLI/Harbor workflows and uses an external LLM judge (documented default: xAI Grok). Although the official eval code declares Apache-2.0 and the Hugging Face dataset page declares MIT, direct runner/judge execution is not integrated with Harnessa's model budget ledger, cancellation, isolated runner, immutable evidence manifests or evaluation UI. [Official runner](https://github.com/Job-Bench/job-bench-eval), [dataset card](https://huggingface.co/datasets/JobBench/job-bench)
- **Harvey LAB:** the official GitHub repository declares MIT and includes a task set and its own execution/evaluation harness. No Harnessa adapter or metered judge integration is installed. [Official repository](https://github.com/HarveyAI/harvey-labs)

No benchmark package or dataset has been downloaded into this repository. The two model-backed calls above were configuration checks only; no benchmark run was started.

After rotation, the project administrator must configure finite project/task/run budgets and authorize bounded calls; then exercise a real isolated agent, 429 failover, and primary/probe contention within the aggregate €20 cap. No call was made in this run.
- **Independent hidden holdout:** Scale must authorize access to the SWE-bench Pro V2 held-out evaluator. Public development results cannot substitute for that evidence.
- **Browser acceptance:** local Chrome is running, but Browser Harness cannot connect because remote debugging is not enabled. The user was asked to enable it; responsive/keyboard/contrast/reduced-motion review and the browser stream reconnect scenario remain unverified pending that step.

The offline implementation and deterministic tests remain distinct from these live integrations. No benchmark score or end-to-end external effect is claimed.
