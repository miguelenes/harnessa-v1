## Implementation delivered so far

- Task board now supports local search, stage filtering, and cursor-based loading of older task rows.
- OpenSpec explorer now has search, section filtering, incremental display, and safe GitHub revision links when repository target and full commit SHA are available.
- Evaluation center projects task readiness and project-authorized immutable Harness² experiment context, distinguishes blocked/unavailable external benchmarks, and does not fabricate scores.
- Setup & health checklist reports administrator, repository-grant, model-route, GitHub installation, and runtime status. Route verification is an explicit one-token action guarded by administrator identity, a checkbox, and the selected project's existing budget controls; its default state makes no provider request.
- API request records are structured JSON with validated request/trace correlation IDs; process-local HTTP counters and latency histograms are protected by an opt-in metrics bearer token.
- Next.js and Astro receive native SVG favicon/app-icon assets. A generated editorial workflow illustration with recorded prompt provenance is integrated into the marketing hero and README.
- Compose persists shared API/worker artifacts in a named volume and adds restart, grace-period, and resource controls.
- Operator, recovery, and acceptance guides document bootstrap, readiness, backup/restore, secrets, and current boundaries.
- Restore now checks the artifact volume before restoring the database, avoiding a database-only partial restore when the target volume is occupied.

## Acceptance gaps that keep the milestone active

1. Harness² provides matched baseline/candidate/composed rollouts, cancellation, stale-lease recovery, and independent holdout grading when configured. The M13 follow-up adds immutable grouped manifests over at most 20 READY probe tasks, a conservative full-context cost dry run checked against remaining probe project/task/run ceilings, an aggregate evaluation ceiling enforced at every model reservation and settlement, idempotent child experiment creation, grouped cancellation, and resume only when every failed child's frozen task/spec/policy still matches. WorkBuddy-Bench remains blocked by the published EU-use restriction. JobBench and Harvey LAB remain unavailable pending dedicated isolated runner, dataset and judge setup; no vendor evaluation result is fabricated.
2. Setup & health now persists a per-project `deployment-default`, `acp-opencode`, or `disabled` execution adapter selection; scheduler dispatch honors disabled/unavailable selections. The project budget contract and ledger counters now separate interactive/primary and probe project/task/run cost and token ceilings while preserving prior shared usage conservatively in each pool. Existing live route checks remain recorded above. A real authorized GitHub App installation/repository, primary/probe contention acceptance, and live real-agent workflow have not been exercised.
3. API JSON request logs and token-protected HTTP counters/latency histograms are implemented. Structured worker/model/GitHub correlation, OpenTelemetry span export, queue/stale-lease/dead-letter/spend/effect/artifact-growth metrics and dashboards, and audited operator recovery actions remain incomplete.
4. The final clean-install lifecycle has not been demonstrated from repository grant through READY, isolated agent, clarification, exact-head verification, PR merge, archive/cleanup, learning candidate, and rollback.
5. Required live resilience scenarios remain unverified: bounded probe, provider 429 failover, worker crash/restart, webhook replay, and browser stream reconnect without duplicate effects or budget escape.
6. Restore evidence does not yet include non-empty artifact/provenance data or Git roots. Existing installations with artifacts in the API writable layer need the documented export before recreation.
7. The legacy README raster remains unprovenanced and unused. Full responsive, contrast, reduced-motion, light/dark, keyboard, and accessibility audit remains outstanding.
8. Full clean-install browser acceptance remains incomplete even though the combined 85% coverage threshold is demonstrated.

These are release blockers, not successful acceptance cases. Relevant external owners/configuration are not available in the repository evidence. No benchmark dataset was downloaded or run. AgentSWE-Lite was evaluated as a candidate and rejected as a hidden holdout because its cases are public and its builders have network access; the evaluator service and operator-controlled private dataset remain unprovisioned. The selection rationale and licensing/credential boundaries are recorded in [`acceptance-report.md`](../acceptance-report.md).
