- Durable checkpoint hashes and recovery: an expired lease resumes only from a retained resumable checkpoint; otherwise the run is visibly failed and dead-lettered instead of being silently relaunched.

- Pause/resume/cancel/retry, with active cancellation forwarded through `ExecutionAdapter.cancel`. Stable-key effect reconciliation distinguishes applied, not applied, and unknown results; abandoned `reconciling` work becomes eligible again after 60 seconds.

## Invariants and recovery procedures

1. **PostgreSQL is authoritative.** A state mutation, transition audit, domain event, and outbox row are committed together. Redis publication can repeat after a crash; consumer inbox uniqueness suppresses repeated domain handling.
2. **Redis can be rebuilt.** An administrator calls `POST /ops/dispatch/rebuild` after authorization and Redis recovery. The stream is reconstructed from retained PostgreSQL events for tasks that remain `READY` and `QUEUED`; scheduler eligibility is queried directly from PostgreSQL.
3. **A lease has one current fence.** Claiming locks and checks global/project capacity, assigns a unique run and next fencing token, and commits before execution begins. Heartbeat, checkpoint, completion, and failure writes require the same task/run/owner/token and an unexpired lease.
4. **Expired work does not run twice silently.** The worker first looks for the latest resumable checkpoint. It creates a new fenced run using that checkpoint only when available and below retry limits; without one it marks the old run failed, creates a dead letter, and blocks automatic dispatch.
5. **Retry limits are explicit.** Transient/rate-limited errors get capped exponential delay with jitter; provider `Retry-After` is capped at one hour. Defaults are three attempts, 1,800 seconds total wall time, four global active runs, two active runs per project, and 30-day event retention. Configure through `.env`; event replay is capped at 500 items and Redis stream length at 10,000 by default.
6. **Cancellation prevents another claim immediately.** The command updates run status and cancellation time in PostgreSQL before returning. An active worker observes the state and calls the adapter cancellation hook. A queued task is no longer eligible for a claim.
7. **Unknown effects remain recoverable.** Reconciliation claims database rows in a short transaction, calls its adapter outside that transaction, and stores the result with a retry time. A crash leaves a `reconciling` row that can be reclaimed after its stale window.
8. **Every read is project-scoped.** Task, run, transition, dead-letter, and event routes resolve the project and check the local membership. Event cursors are monotonically increasing within one project and return HTTP 410 after retention expires.

For an operator recovery, inspect `GET /projects/{project_id}/dead-letters`, review the run/checkpoint history, then call `POST /dead-letters/{id}/replay` with a reason and `Idempotency-Key`. Replay requires project operator or administrator membership, records the command and event, and returns the task to `READY`/`QUEUED`. Operators can pause, resume, cancel, or retry through `POST /tasks/{id}/commands` using `If-Match` and an idempotency key. The event replay route is `GET /projects/{id}/events?after={cursor}&limit={n}`.

No database transaction is held while an execution or effect adapter performs external work. The worker's production executor is intentionally unconfigured, and the event endpoint is HTTP replay only; SSE/AG-UI subscriptions are left for their later milestone.

## Adapter hooks and remaining setup

- A real `ExecutionAdapter` must declare availability/name, implement execution with checkpoint and cancellation callbacks, and honor a current fencing token through the supplied run context. The default adapter stays disabled until that implementation is configured.
- An `EffectReconciler` must use stable external-effect keys and report `applied`, `not_applied`, or `unknown`; no external effects are issued by the current worker.
- LiteLLM routing/spend control, OpenSpec discovery, ACP execution, AG-UI streaming, Harness² probes, artifact storage, OIDC, and GitHub synchronization remain reserved for later milestones.
- Task and recovery endpoints are API-only. There is no task board UI, artifact model/API, or live event subscription yet.
- To run integration tests locally, create a disposable database whose name ends in `_test`, use a dedicated Redis database (the README uses database 1), and pass `TEST_DATABASE_URL` plus `TEST_REDIS_URL`. The suite truncates the database and flushes that Redis database.

## Milestone 3 boundary

Milestone 3 can add LiteLLM routing and spend controls on top of `ExecutionAdapter` without changing the PostgreSQL task/outbox authority. It must not treat a model response as permission to perform an external effect; effect intents and reconciliation remain the durable boundary.
