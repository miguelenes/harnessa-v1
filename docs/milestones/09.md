## Delivered

- Dispatch now requires a current READY interview, exact repository base and approved specification revision, current policy and budget counters, compatible model route/capabilities, and an administrator-approved manifest whose tracked source hash and base revision still match. The scheduler mounts the approved specification and selected harness context read-only into the exact-base task workspace and binds these revisions into the run.
- Added an immutable administrator-approved verification manifest with digest-pinned images, argument-vector commands, criteria mappings, fixed time/output/resource limits, safe artifact paths, and admin-supplied protected fixture snapshots. The verifier shallow-fetches each exact candidate commit inside a per-command rootless Podman tmpfs volume, default-capped at 1 GiB (`VERIFICATION_WORKSPACE_LIMIT_BYTES`, configurable from 16 MiB to 4 GiB). This enforces the bound during source materialization and writable test execution; exhaustion is visibly unverified. The command container has no network, a read-only root, dropped capabilities, no-new-privileges, bounded CPU/memory/PIDs/tmpfs, and read-only fixture mounts. Each command container is named and forcibly removed on timeout/cancellation before the volume is removed; both container and volume cleanup results are checked and cleanup failure remains visibly unverified.
- Captured exit status, sanitized bounded output, duration, exact source revision, output artifact hashes/size/content where safe, and a requirement/scenario matrix. Failed, missing, timed-out, manual, or unavailable checks cannot become automatic passes. A model response cannot override command evidence.
- Added a fenced verifier worker stage and bounded repair path using the existing shared attempt, spend, and wall-clock policies. Repair invalidates prior review bundles and returns sanitized verifier evidence. The Harness² hook is present and explicitly inactive for M12.
- Added immutable content-addressed review bundles containing code and specification diffs, exact base/head, verification matrix/evidence, costs and route ledger, specification/harness/manifest revisions, and agent/model/image identifiers. Reviewer actions bind to the bundle digest and head. The publication port currently uses a local publisher; a GitHub publication provider belongs to M10.
- OpenSpec archive preparation runs the pinned CLI against a disposable copy of the approved workspace. It applies the frozen approved-spec diff and generated archive diff in order to an isolated Git index, creates an immutable candidate commit pinned under `refs/harnessa/review-candidates/<run-id>-f<fence>`, then verifies that exact commit. The bundle binds both implementation and candidate heads; review routes check the archive digest and verifier-reported candidate SHA before allowing reviewer actions. An unverified outcome cannot mark the candidate head verified even when its expected SHA matches. The checked-out branch and protected default branch are not moved. Review approval is blocked if archive preparation or final-head verification is unavailable. Manual integration requires operator evidence, expected base SHA, and a per-repository lock; archive, learning, and candidate-ref cleanup are separate recoverable post-integration steps.
- Fixed dispatch to use the same specification workspace manager instance that created the approved workspace. The rootless Podman process receives the host home for its local image store while the container receives `HOME=/tmp` on its isolated tmpfs; this was required for real local execution.

## Recovery and rollback

- Before merge, discard the milestone branch to roll back the implementation. After merge, revert the M9 merge commit through the normal protected `main` workflow.
- The verifier uses disposable workspaces and immutable execution/bundle records; a failed or interrupted verifier must be retried under a new lease fence. Do not delete evidence to clear a blocked task.
- Review candidate commits are held by `refs/harnessa/review-candidates/<run-id>-f<fence>` in the configured local source repository. After integration evidence is recorded and cleanup is explicitly confirmed, remove the corresponding ref with `git -C <repository> update-ref -d refs/harnessa/review-candidates/<run-id>-f<fence>`; do not remove refs for pending or failed integrations.
- Manual integration is idempotent by stable key and expected base SHA. Archive, learning, and cleanup have independent statuses and can be retried separately after integration.
- If an OpenSpec archive preview fails, the bundle remains visible but reviewer approval is blocked. Rebuild it from the approved interview revision; never apply it directly to the protected default branch.
