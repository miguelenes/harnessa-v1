## Implemented at this checkpoint

- Added GitHub App configuration, installation and explicit repository opt-in records; organization-admin actor mapping; scoped installation tokens; and permission/connection reporting. App and webhook secrets are stored as opaque references and are forwarded only to the API and worker services in Compose.
- Added bounded raw-body HMAC verification and a transactional PostgreSQL webhook inbox/outbox with delivery uniqueness, lease/retry processing, and authenticated repair controls.
- Added inbound issue-to-interview creation for labeled, opted-in issues from mapped operators; structured question/revision-bound answer comments; issue-edit conflict detection; and revocation handling for installation/repository removal.
- Added durable, stable-key issue-comment effects and exact-base review-branch/PR publication from the verified local Git revision. Publication checks for an existing PR/branch after ambiguous outcomes and records remote PR identity and head data. Completed check-run/check-suite events trigger fresh PR-head and check-run queries before recording the required-check set; a stale head is ignored.
- Added durable, stable-key outbound issue creation and commit-status effects. Issue creation searches bounded issue pages for its correlation marker after ambiguous writes and stores the resulting GitHub object ID/number. Commit-status effects reconcile the latest status for a task context before writing, and reject stale task-version intents.
- Added a five-minute bounded poll of up to 25 tracked, opted-in PRs/installation records to recover missed PR/check/review and installation/repository-access webhooks. It refreshes each PR and current required-check set, reconciles newly observed mapped review states, rechecks installation grants and repository availability, records exact-head merge evidence only after fresh checks and current mapped approval evidence, and returns an unmerged closed or drifted PR to bounded remediation when attempts remain. A merged PR whose head differs from the reviewed head remains explicitly unverified and is not automatically retried.
- Added a durable post-integration worker for archive finalization, optional learning outcome, and cleanup. The archive outcome is bound to the verified bundle digest/head and merge revision; cleanup removes only the exact Harnessa candidate ref and owned interview workspace; a task reaches `DONE` only after archive and cleanup succeed and learning has a terminal outcome. The learning outcome is recorded as skipped because no project learning hook is configured in M10.
- Added an authenticated GitHub status/repair UI and the [GitHub App setup guide](../integrations/github-app.md), Compose configuration, environment examples, and compatibility notes.
