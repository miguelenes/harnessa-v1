## Implementation evidence

- Upstream Harness² is pinned at `1cfe254e8d25b15f37048c3730134686abe60335` under Apache-2.0, with eight upstream component categories mapped through a product manifest.
- Five additive database tables store fixed project policy, task experiments, probe evidence references, scoped candidate experiences and append-only promotion/rollback decisions.
- Probe model calls use Harnessa's task/project budgeted probe pool and idempotency key. Candidate edits are validated against upstream's OpenCode surface, bounded, isolated beneath a candidate workspace, and checked for path escapes and named host-policy edits. Holdout-shaped context is rejected before dispatch.
- The ACP prompt now places repository and candidate harness guidance before a final immutable host-policy reminder; the added ACP regression test verifies the ordering and prohibited operations.
- Project API operations require membership; experiment creation requires an operator, HARNESS_PROBE task and ready frozen specification. Promotion and rollback require an administrator and the exact reviewed digest. Post-merge learning only produces an expiring `candidate` experience from a successful experiment and explicit evidence refs.
- Harness Studio reads the authorized project manifest, experiment history, probe diffs and experience evidence and offers reviewed promotion/rollback actions.
- `HarnessExperimentWorker` claims and heartbeats durable rows, recovers stale claims under a new fence, and dispatches matched baseline/candidate runs through the existing ACP adapter on the probe pool. It re-executes the selected final harness as composed evidence, stores bounded behavior-shape traces and run outcomes, attributes model requests to task/run budgets, and fences cancellation/policy drift. Before any sandbox/model dispatch, it scans the exact frozen Git tree and fails closed on holdout, hidden, answer, grader or rubric paths; ACP unavailable leaves queue rows queued. A live post-failure trace showed that an incomplete baseline could be selected for holdout grading; the worker now records `not_run` with `composed_artifact_unavailable` and persists it without calling the grader. Focused tests cover that fence alongside loop ownership, safe trace capture, unique bounded evidence labels, selected-harness re-execution, missing-composition failure, restricted-source rejection and queue preservation when ACP is unavailable.
- After CAS artifacts are committed, the worker creates a frozen holdout manifest of task/base/spec/policy/harness identity and artifact references, then invokes the injected `HarnessEvaluator`. Raw receipts are stored by content address; only status, judge revision and receipt digests are attached to the experiment. Grader feedback and scores are not copied into probe traces or agent context. The acceptance evaluator is a local HTTP process (`local-holdout-v1:ed22ac26a00f686d2c2c`) with a private synthetic model-cost holdout file and bearer-authenticated `/evaluate` endpoint; the OpenCode worker receives only the pass/fail receipt. The process and file are permission-isolated from the agent container, but are operated on the same host; no third-party evaluator account or external benchmark dataset is claimed. This setup is sufficient for the project’s small synthetic acceptance task and does not establish independent institutional evaluation.
- The final review found the post-merge learning hook was hardcoded off; this was fixed on the branch and independently re-reviewed. A subsequent finding that verification feedback could follow the host-policy reminder was fixed in `dddb1d5`, tested, independently re-reviewed, and its review thread resolved.
