## Implementation

- Pinned the official stable agent-client-protocol==0.12.1 API in pyproject.toml and uv.lock. It was exercised on Python 3.12.15. The adapter uses connect_to_agent, SDK schemas, ACP protocol v1, permission callbacks, session updates, prompt lifecycle, and cancellation. The official release listings show 1.0.0 release candidates; they were not adopted because they are pre-release schema/runtime changes.
- Added a bounded ACP stdio transport: 1 MiB frames, 64 MiB total bytes, 30,000 messages, 300-second idle receive deadline, and 10,000 ACP updates. Protocol stdout stays separate from drained stderr. Thought/message content and tool input/output are not retained. SDK types remain behind the adapter boundary.
- Added the OpenCode ACP registry entry and a genuine supported path using OpenCode 2.0.32. Its ephemeral provider configuration exposes only the Harnessa route and a per-run bearer token. A trusted host broker reaches the sandbox through a private Unix socket and static loopback-only relay. The broker binds requests to organization, project, task, run, and fencing token; attempt identity remains with Harnessa and the sandbox labels. It ignores agent-selected model routing, enforces request and output bounds, checks cancellation/current fencing, and calls Harnessa's existing ModelRouter for both completion and streaming. Provider credentials remain behind the existing LiteLLM boundary.
- Kept all container-engine operations on the trusted host. The rootless Podman sandbox uses a digest-pinned image, --network=none, read-only root filesystem, dropped capabilities, no-new-privileges, userns=keep-id, and bounded CPU, memory, process, file, and tmpfs resources. The only writable user bind is /workspace; the socket, config, and relay are read-only. No provider keys or engine socket are mounted.
- Added per-run managed clones at the requested full base commit, with independent Git metadata, no configured remote, and no mount of the source checkout. Success removes the workspace; failure preserves it for operator recovery. Rootless Podman resources carry installation/run/task/attempt/fence labels; startup and periodic reconciliation remove only stale resources owned by this installation.
- Added scoped filesystem permission handling, traversal/symlink escape rejection, shell execution confined to the sandbox, and network-fetch denial. Checkpoints/progress use Harnessa's scheduler and durable events. Artifact publication validates the active lease/fence before and after CAS storage; stale writes cannot create a durable reference. Referenced artifacts are retained; old unreferenced CAS blobs are reconciled after the grace period.
- Task/run/attempt identity, leases/fences, model budgets, questions, domain events, and external-effect intent/reconciliation remain under Harnessa authority. The broker exposes only the scoped model route; no clarification or external-effect tool was added.
- Added disabled-by-default execution and broker configuration. The existing worker remains the scheduler owner; the Compose worker receives no Podman engine access. The clarification interface and session/ask_orchestrator remain untouched.
- Preserved OpenAPI-to-TypeScript generation. The existing ModelMessage contract gained tool_calls so OpenAI-compatible tool-call history can cross Harnessa's existing model-router contract; the generated TypeScript contract contains that field. No ACP SDK types were added to public APIs.

## Limitations

- No provider-backed repository edit or live LiteLLM route was exercised. The feature remains disabled by default. A future live run requires an explicitly authorized provider credential and spending ceiling, kept behind LiteLLM.
- The Compose worker has no Podman executable or engine access. A separately managed trusted host worker with database/Redis access and private workspace/state/artifact directories is required to run ACP outside these local smokes.
- The workspace-size limit is a one-second watchdog and can overshoot; use filesystem/project quotas before treating 4 GiB as a hard aggregate limit.
- Podman is the only implemented and tested backend. Docker parity is unverified.
- OpenCode advertises session resume, but its session store is not persisted; lease recovery starts a fresh ACP session at the exact prior base commit with bounded, redacted durable context.
- Failed workspaces are preserved for audit/operator recovery; automated workspace-retention deletion and a public artifact retrieval endpoint are not implemented.

## Recovery and rollback

- Disable/stop: keep ACP_EXECUTION_ENABLED=false and ACP_MODEL_BROKER_ENABLED=false (both default to false); stop the separately managed host worker. The Compose worker does not own Podman containers.
- Lost worker: the Harnessa scheduler expires the lease and gives a later attempt a higher fence. Startup and 30-second reconciliation inspect only containers bearing this installation's owner labels; stale owned containers are removed, live current-fence containers remain. Failed workspaces are preserved for review.
- Artifact cleanup: referenced CAS blobs are retained. Unreferenced blobs are eligible only after one hour. Back up the artifact root with PostgreSQL before operations or rollback.
- Schema rollback: stop the host worker, take a PostgreSQL backup, preserve the artifact root, then from apps/api run DATABASE_URL=<target URL> uv run python -m alembic downgrade b11f10974e82. This drops M5 artifact metadata and the internal task event sequence; CAS files remain on disk. Do not roll back M5 data without a recoverable backup.
- Runtime decision: no LangGraph deployment or state conversion occurred; there is no second checkpoint owner to switch back to.
