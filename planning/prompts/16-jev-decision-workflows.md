## Goal

Use TypeSafe System One/Jev for narrow, structured judgments that application code can act on, reducing avoidable expensive LLM calls and making workflow branching measurable. Keep deterministic rules for policy, authorization, state transitions, and exact constraints. Keep general-purpose coding, explanation, and open-ended planning with suitable LLM/agent runtimes.

## Implement

1. Add a versioned decision-workflow registry. A workflow defines a stable ID/revision, input schema, allowed context sources, typed atomic questions, result schema, deterministic composition code, decision thresholds, abstain/escalate behavior, test fixtures, and maximum cost/latency. Support only the question types and result fields confirmed by the pinned TypeSafe API (currently documented primitives include Choice, Score, and Noul). Record the actual served Jev model version for every execution.
2. Implement a provider adapter for Jev that checks endpoint, authentication, schema/version, timeout, retry, cancellation, and supported question cardinality/capabilities at setup. Use only an officially supported integration path. If using a LiteLLM provider or gateway path, prove that it preserves System One question/response semantics, probabilities/confidence, actual model identity, and cost attribution; do not silently coerce Jev into chat completions. Keep direct TypeSafe use behind the same adapter interface where gateway support is incomplete.
3. Select the first bounded Harnessa workflows with a value estimate and risk review. Candidates include task intake classification (bug/feature/docs/security, complexity, repository/tool needs), route-tier selection among already-authorized deployments, reviewer/escalation priority, clarification-needed signals, safe categorization of inbound issue/PR events, and Harness² task/domain/subset selection. Keep irreversible/high-impact decisions behind existing explicit approval and policy guards. Do not let a Jev result set READY, merge, close an issue, change grants, promote a harness, or spend beyond policy.
4. Decompose compound judgments into independent narrow questions. Pass only the minimum state needed, with exact task/spec/repository/policy revisions and a content digest. Code combines typed outputs and deterministic facts. Add explicit outcomes for insufficient evidence, out-of-distribution input, missing fields, disagreement, timeout, and model unavailability. Do not persist raw prompt/context content by default; record workflow revision, input digest/source links, outputs, model version, latency, cost, and redaction status.
5. Implement a conservative decision cascade: deterministic checks first; Jev for supported low-latency structured decisions; an authorized LLM or human escalation when policy says needed. For model routing, Jev may select a class/tier from a finite candidate set or estimate task attributes; application code then filters by route capability, provider availability, remaining budget, context size, and project policy and selects the actual deployment. Preserve an explicit safe fallback. Session-affinity or other stateful routing must be part of the input policy and evaluation manifest.
6. Keep `confidence` and per-choice probabilities as model outputs, not automatic guarantees of calibration on Harnessa data. Calibrate/select thresholds against an independently labeled, versioned Harnessa dataset. Support selective prediction: measure accuracy at coverage, abstention/escalation, and risk-weighted errors. High-risk false negatives must have stricter gates than routine classifications.
7. Integrate each decision call into the model request ledger and prompt 11 evidence graph. Attribute Jev classifier cost separately from downstream model costs and avoid double charging if the gateway already records it. Reserve a conservative decision-stage bound before dispatch, settle from authoritative usage where available, and leave absent usage unknown. Apply caching only to deterministic, low-risk decisions keyed by workflow revision, input-state digest, model version, and policy revision, with an explicit expiry/freshness rule.
8. Build frozen paired evaluations against appropriate baselines: deterministic baseline where available, fixed `tier-pro`/approved fixed model, ordinary LLM structured-output baseline, and Jev→LLM cascade. Run each on the same task state and workflow logic, randomize arm order, disable unrelated caching/compression optimizations unless separately controlled, include all classifier/retry/fallback costs, and use blinded human review or independent adjudicated labels. The dataset's labels must not be produced solely by Jev or by the candidate workflow itself.
9. Report per-task and risk-stratified quality, coverage, abstention/escalation, false-positive/false-negative costs, agreement, calibration plots/metrics (for example Brier score and reliability bins where probability semantics support them), p50/p95 latency, total dollars per accepted outcome, provider-tier distribution, fallback/error rate, actual Jev version, sample size, confidence intervals where appropriate, and missing evidence. Keep prompt/response content out of reports unless a separately authorized private review requires transient display.
10. Add shadow mode before any routing effect. Compare Jev decisions to existing behavior without changing the selected route or workflow. Enable limited policy-controlled use only after acceptance, with runtime kill switch, drift/quality/cost guardrails, and automatic return to known-safe routing on missing/stale configuration or Jev outage. Record every rollout and rollback decision.

Treat prompt 3's route registry, capability checks, workload pools, budgets, reservations, and request ledger as the single model-routing authority. Extend its route selection decision point instead of creating a competing router. Detect whether the configured LiteLLM route already invokes Jev; avoid duplicate classification calls and reconcile Jev cost exactly once.
